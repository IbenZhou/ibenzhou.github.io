Overview

This unit introduces the data structures array, ArrayList, and 2D array, which let a program represent collections of related data with a single variable instead of many separate variables. Arrays have a static size, which limits how many elements they can store and makes reordering elements challenging; an ArrayList object has a dynamic size and provides methods for inserting and deleting elements, making reordering and shifting easier. Choosing the right data structure becomes increasingly important as the size of a data set grows. A 2D array is best used to represent a table, and unlike 1D arrays, it requires nested iteration to traverse and access all elements, most easily in row-major order though other patterns such as column-major are also important. The unit also covers standard algorithms for data structures, including two searching algorithms (linear and binary search) and three sorting algorithms (selection, insertion, and merge sort). Finally, students learn recursion, a powerful technique in which a problem is solved by solving smaller or simpler versions of the same problem, and they practice tracing recursive methods. Privacy concerns around storing large amounts of personal data, algorithmic bias, and data quality are also examined.

In this unit you will learn to:

  • Explain the risks to privacy from collecting and storing personal data, and recognize data quality and bias issues when using a data set.
  • Represent patterns and algorithms that involve real-world data sets using written language or diagrams.
  • Create and access elements in one-dimensional (1D) arrays and two-dimensional (2D) arrays.
  • Traverse arrays, ArrayList objects, and 2D arrays in a variety of orders and implement standard algorithms on them.
  • Read data from a text file using the File and Scanner classes, and use the Integer and Double wrapper classes.
  • Use ArrayList methods and implement standard ArrayList algorithms.
  • Determine the results of linear search, selection sort, insertion sort, binary search, and merge sort.
  • Determine the result of executing recursive methods, and trace recursive searching and sorting.
💡 Exam Tip
  • Array vs. ArrayList: On FRQ Question 3 (“Data Analysis with ArrayList”), the collection is an ArrayList, so you must use the methods size(), get(), set(), add(), and remove() — NOT square brackets and length. Arrays use arr.length (attribute, no parentheses); ArrayList uses list.size() (method call). Confusing the two is a common point-losing mistake.
  • Row-major vs. column-major: On FRQ Question 4 (“2D Array”), the standard nested loop for (int r...) for (int c...) traverses row-major (across each row). Swapping the loops gives column-major (down each column). When using nonstandard traversals, adjust the loop bounds carefully — the number of rows is arr.length and the number of columns is arr[0].length.
  • Off-by-one errors: Valid indices are 0 through length - 1. Writing i <= arr.length causes an ArrayIndexOutOfBoundsException. When shifting elements during insertion or deletion in an ArrayList, remember to adjust the loop counter so you don’t skip or double-process an element.
  • Recursion: Recursion is assessed on the multiple-choice section only — you trace calls and describe behavior; you are not asked to write recursive code. Every recursive method needs at least one base case that halts the recursion; without it you get infinite recursion and eventually a StackOverflowError.

Topic 4.1 — Ethical and Social Issues Around Data Collection

Key Concepts

EK Concept Key Idea
4.1.A.1 Privacy risk When using a computer, personal privacy is at risk. When developing new programs, programmers should attempt to safeguard the personal privacy of the user.
4.1.B.1 Algorithmic bias Algorithmic bias describes systemic and repeated errors in a program that create unfair outcomes for a specific group of users.
4.1.B.2 Collection method and bias Programmers should be aware of the data set collection method and the potential for bias when using this method before using the data to extrapolate new information or draw conclusions.
4.1.B.3 Data quality Some data sets are incomplete or contain inaccurate data. Using such data in the development or use of a program can cause the program to work incorrectly or inefficiently.
4.1.C.1 Appropriate data set Contents of a data set might be related to a specific question or topic and might not be appropriate to give correct answers or extrapolate information for a different question or topic.

Learning Objective 4.1.A: Explain the risks to privacy from collecting and storing personal data on computer systems.

Learning Objective 4.1.B: Explain the importance of recognizing data quality and potential issues when using a data set.

Learning Objective 4.1.C: Identify an appropriate data set to use in order to solve a problem or answer a specific question.

Why this matters: An app that tracks your location, purchases, or messages is collecting personal data. Even well-intentioned programs can leak that data if it is stored carelessly, and biased or incomplete data sets can produce unfair or incorrect results. A programmer must ask: Is this data set appropriate for my question? Was it collected fairly? Is it complete and accurate?

Example Code

// Illustrative example: what happens when a data set is incomplete?
// A fitness app stores the number of steps users walked each day.
// Some entries are missing (0) because a user forgot their phone.

int[] steps = {8200, 0, 9500, 0, 6100, 11000, 4000}; // 0 = missing data

int total = 0;
for (int s : steps) {
    total += s;
}
double average = total / (double) steps.length;
System.out.println("Daily average steps: " + average);  // 5543.57... but
// is this fair to the user? The zeros are NOT real step counts —
// they are missing data, so this average is misleading.

// Fix: only average the days that actually have data (value > 0).
int sum = 0;
int count = 0;
for (int s : steps) {
    if (s > 0) {          // skip the missing-data entries
        sum += s;
        count++;
    }
}
System.out.println("Average of recorded days: " + (sum / (double) count));
// 8280.0 — a much more accurate representation of the user.

This snippet shows [4.1.B.3]: incomplete data (zeros standing in for missing values) causes a program to report incorrect conclusions. Recognizing the data set’s quality before drawing conclusions is a core skill of this topic.

Topic 4.2 — Introduction to Using Data Sets

Key Concepts

EK Concept Key Idea
4.2.A.1 Data set A data set is a collection of specific pieces of information or data.
4.2.A.2 Processing data Data sets can be manipulated and analyzed to solve a problem or answer a question. When analyzing data sets, values within the set are accessed and utilized one at a time and then processed according to the desired outcome.
4.2.A.3 Diagramming data Data can be represented in a diagram by using a chart or table. This visual can be used to plan the algorithm that will be used to manipulate the data.

Learning Objective 4.2.A: Represent patterns and algorithms that involve data sets found in everyday life using written language or diagrams.

The “process each value one at a time” pattern: Nearly every data-processing algorithm has the same shape: (1) decide what to do to a single value, (2) repeat that step for each value in the set. If you can describe step (1) in words — “find the largest”, “count the ones that are overdue”, “add this to the running total” — then you have already designed the algorithm that a loop will carry out.

Working example: A music streaming service has a list of the seconds each user spent listening yesterday. To answer “what fraction of users listened for more than one hour?”, plan: look at each user’s time one at a time, count how many exceed 3600 seconds, then divide by the total number of users.

Example Code

// Data set: high temperatures (°C) for one week, in order by day.
int[] temps = {21, 24, 19, 26, 28, 25, 23};

// Question: How many days were hotter than 25°C?
// Pattern: look at each value one at a time and decide if it qualifies.
int count = 0;
for (int t : temps) {
    if (t > 25) {
        count++;          // process ONE value, then move on
    }
}
System.out.println("Days over 25°C: " + count);

// The same idea, represented first as a diagram:
//   Row 1 of a table:  day       1   2   3   4   5   6   7
//   Row 2 of a table:  temp      21  24  19  26  28  25  23
//   Row 3 of a table:  >25°C?    no  no  no  yes yes no  no   -> 2

The table in the comment is a [4.2.A.3] diagram of the algorithm: each column is one value, the last row is the decision applied one value at a time.

Topic 4.3 — Array Creation and Access

Key Concepts

EK Concept Key Idea
4.3.A.1 Array An array stores multiple values of the same type. The values can be either primitive values or object references.
4.3.A.2 Fixed length The length of an array is established at the time of creation and cannot be changed. The length of an array can be accessed through the length attribute.
4.3.A.3 Default values When an array is created using the keyword new, all of its elements are initialized to the default values for the element data type. Default value for int is 0, for double is 0.0, for boolean is false, and for a reference type is null.
4.3.A.4 Initializer list Initializer lists can be used to create and initialize arrays.
4.3.A.5 Indexed access Square brackets [] are used to access and modify an element in a 1D array using an index.
4.3.A.6 Valid indices The valid index values for an array are 0 through one less than the length of the array, inclusive. Using an index value outside of this range will result in an ArrayIndexOutOfBoundsException.

Learning Objective 4.3.A: Develop code used to represent collections of related data using one-dimensional (1D) array objects.

Three ways to create an array:

Way Code Result
new with size int[] scores = new int[5]; {0, 0, 0, 0, 0} (default values)
Initializer list int[] scores = {92, 88, 75, 90, 84}; elements set immediately
new + initializer list int[] scores = new int[] {92, 88, 75, 90, 84}; same as above (allowed on AP)

Access rules: scores[0] is the first element; scores[scores.length - 1] is the last element. scores.length is the number of elements — note length is an attribute, not a method, so there are no parentheses.

Example Code

// Create an array with a size — all elements get default values.
int[] quiz = new int[4];          // {0, 0, 0, 0}
double[] temps = new double[3];   // {0.0, 0.0, 0.0}
boolean[] flags = new boolean[2]; // {false, false}
String[] names = new String[3];   // {null, null, null} — reference default

// Create and initialize with an initializer list.
int[] scores = {92, 88, 75, 90, 84};

// Access an element with [index] (valid: 0 .. length-1).
System.out.println(scores[0]);   // 92
System.out.println(scores[4]);   // 84
System.out.println(scores.length); // 5  (attribute, no parentheses)

// Modify an element with [index].
scores[2] = 80;                  // scores is now {92, 88, 80, 90, 84}

// BAD: index out of range.
// System.out.println(scores[5]);  // ArrayIndexOutOfBoundsException

// Arrays of object references: each cell holds a reference to a String.
names[0] = "Ana";
names[1] = "Ben";
// names[2] is still null until assigned.

Topic 4.4 — Array Traversals

Key Concepts

EK Concept Key Idea
4.4.A.1 Traversal Traversing an array is when repetition statements are used to access all or an ordered sequence of elements in an array.
4.4.A.2 Indexed loops Traversing an array with an indexed for loop or while loop requires elements to be accessed using their indices.
4.4.A.3 Enhanced for loop variable An enhanced for loop header includes a variable, referred to as the enhanced for loop variable. For each iteration, the enhanced for loop variable is assigned a copy of an element using its index.
4.4.A.4 Copy, not reference Assigning a new value to the enhanced for loop variable does not change the value stored in the array.
4.4.A.5 Objects in enhanced for When an array stores object references, the attributes can be modified by calling methods on the enhanced for loop variable. This does not change the object references stored in the array.
4.4.A.6 Equivalent loops Code written using an enhanced for loop to traverse elements in an array can be rewritten using an indexed for loop or a while loop.

Learning Objective 4.4.A: Develop code used to traverse the elements in a 1D array and determine the result of these traversals.

Which loop should I use?

Situation Use
Read each element, front to back, no index needed Enhanced for loop
Need the index (e.g., set an element, compare neighbors, traverse backward) Indexed for loop
Stop early, skip elements, or condition depends on the index Indexed for / while

Critical rule (EK 4.4.A.4): The enhanced for loop variable is a copy. Changing it changes nothing in the array. To actually modify an array element, use arr[i] = ... in an indexed loop.

Example Code

int[] scores = {92, 88, 75, 90, 84};

// Enhanced for loop: variable x is a COPY of each element.
for (int x : scores) {
    x = 0;               // changes the copy only — scores unchanged!
}
System.out.println(scores[0]);   // still 92

// Indexed for loop: can actually modify the array.
for (int i = 0; i < scores.length; i++) {
    scores[i] = scores[i] + 5;   // raises every score by 5
}
// scores is now {97, 93, 80, 95, 89}

// Traverse from the LAST element to the FIRST.
for (int i = scores.length - 1; i >= 0; i--) {
    System.out.print(scores[i] + " ");   // 89 95 80 93 97
}
System.out.println();

// Enhanced for loop with an array of String references.
String[] names = {"Ana", "Ben", "Cara"};
for (String n : names) {
    n = "Zed";           // reassigning the copy — names unchanged
}
for (String n : names) { // prints Ana Ben Cara
    System.out.print(n + " ");
}
System.out.println();

Topic 4.5 — Implementing Array Algorithms

Key Concepts

Learning Objective 4.5.A: Develop code for standard and original algorithms for a particular context or specification that involves arrays and determine the result of these algorithms.

The nine standard array algorithms (EK 4.5.A.1):

Standard algorithm Idea Typical loop pattern
Determine a minimum or maximum value Compare each element to the current best if (arr[i] > max) max = arr[i];
Compute a sum or average Add each element to an accumulator sum += arr[i]; then sum / arr.length
Determine if at least one element has a property Search; stop early on first success if (found) break;
Determine if all elements have a property Search; stop early on first failure if (!ok) break;
Determine the number of elements with a property Count every match if (matches) count++;
Access all consecutive pairs Visit each element with its neighbor for i in 0..len-2: pair (arr[i], arr[i+1])
Determine presence/absence of duplicates Check pairs or use nested loops if (arr[i] == arr[j]) duplicate = true;
Shift or rotate elements left or right Save the overflow element, move the rest, put it back index math with % or temporary variable
Reverse the order of the elements Swap from both ends toward the middle swap(arr[i], arr[len-1-i])

Two key “look-ahead” patterns to memorize:

  • Consecutive pairs: the loop runs i from 0 to length - 2, so arr[i + 1] never goes out of range.
  • Reverse: the loop runs only while i < j, so each pair is swapped exactly once.

Example Code

int[] scores = {92, 88, 75, 90, 84};

// 1) Maximum value
int max = scores[0];                       // assume first is biggest
for (int i = 1; i < scores.length; i++) {
    if (scores[i] > max) {
        max = scores[i];                   // new best found
    }
}                                          // max == 92

// 2) Sum and average
int sum = 0;
for (int s : scores) {
    sum += s;
}
double average = sum / (double) scores.length;  // 85.8

// 3) Count elements above 85
int count = 0;
for (int s : scores) {
    if (s > 85) {
        count++;
    }
}                                          // count == 2

// 4) At least one element is odd
boolean hasOdd = false;
for (int s : scores) {
    if (s % 2 != 0) {
        hasOdd = true;
        break;                             // can stop early
    }
}

// 5) All elements are positive
boolean allPositive = true;
for (int s : scores) {
    if (s <= 0) {
        allPositive = false;
        break;
    }
}

// 6) Consecutive pairs: print each pair (scores[i], scores[i+1])
for (int i = 0; i < scores.length - 1; i++) {
    System.out.println(scores[i] + " " + scores[i + 1]);

Topic 4.7 — Wrapper Classes

Key Concepts

EK Concept Key Idea
4.7.A.1 Integer and Double Part of the java.lang package. An Integer object is immutable — once created, its attributes cannot be changed. A Double object is immutable the same way.
4.7.A.2 Autoboxing The automatic conversion the Java compiler makes between primitive types and their corresponding object wrapper classes (int to Integer, double to Double). Applied when a primitive value is passed as a parameter to a method that expects the wrapper object, or assigned to a variable of the wrapper class.
4.7.A.3 Unboxing The automatic conversion from the wrapper class to the primitive type (Integer to int, Double to double). Applied when a wrapper object is passed to a method that expects the primitive, or assigned to a primitive variable.
4.7.A.4 Integer.parseInt static int parseInt(String s) returns the String argument as an int.
4.7.A.5 Double.parseDouble static double parseDouble(String s) returns the String argument as a double.

Learning Objective 4.7.A: Develop code to use Integer and Double objects from their primitive counterparts and determine the result of using these objects.

Why do we need wrappers? An ArrayList can only store object references, not primitives. Wrapper classes “wrap” an int or double in an object so the value can go into an ArrayList<Integer> or ArrayList<Double>. Autoboxing and unboxing make the conversion invisible in your code.

The four conversions:

int x = 5;
Integer boxed = x;        // autoboxing:  int -> Integer (assignment)
Integer boxed2 = Integer.valueOf(7); // explicit boxing (fine but not needed)
int y = boxed;            // unboxing:   Integer -> int (assignment)
int z = Integer.parseInt("42"); // String -> int (class method, NO autoboxing)
double d = Double.parseDouble("3.5"); // String -> double

Example Code

Double height = 1.75;             // 1.75 (a double) is boxed into a Double

// Unboxing when assigning to a primitive variable.
int years = age;                  // Integer 17 unboxed into int
double meters = height;           // Double 1.75 unboxed into double

// Wrappers let primitives be stored in an ArrayList.

int back = quizScores.get(0);     // returned Integer is unboxed to int
// Note: using the raw type ArrayList (no <Integer>) is allowed but less safe.

// Parsing strings into numbers.
String numText = "345";
int n = Integer.parseInt(numText);     // n == 345
String ratioText = "2.5";
double r = Double.parseDouble(ratioText); // r == 2.5

// Immutability: you cannot change an Integer's value, you only reassign.
Integer a = 10;
a = a + 5;        // this creates a NEW Integer object; a now refers to it
// (a += 5 unboxes, adds, and reboxes — the original Integer 10 is unchanged)

Topic 4.9 — ArrayList Traversals

Key Concepts

EK Concept Key Idea
4.9.A.1 Traversal Traversing an ArrayList is when iteration or recursive statements are used to access all or an ordered sequence of the elements in an ArrayList.
4.9.A.2 Deleting during traversal Deleting elements during a traversal of an ArrayList requires the use of special techniques to avoid skipping elements.
4.9.A.3 Out-of-range access Attempting to access an index value outside of its range will result in an IndexOutOfBoundsException.
4.9.A.4 Enhanced for restriction Changing the size of an ArrayList while traversing it using an enhanced for loop can result in a ConcurrentModificationException. Therefore, when using an enhanced for loop to traverse an ArrayList, you should not add or remove elements.

Learning Objective 4.9.A: Develop code used to traverse the elements of an ArrayList and determine the results of these traversals.

The deletion trap (EK 4.9.A.2) — this is a favorite exam topic:

// WRONG — removes 3 but SKIPS 4, and later hits index out of bounds:
for (int i = 0; i < list.size(); i++) {
    if (list.get(i) == someValue) {
        list.remove(i);   // everything shifts LEFT, so i++ skips the next element
    }
}
Situation Technique
Remove elements by value while scanning forward Decrement i after each remove(i) (i.e., don’t let i advance past the shifted element)
Remove elements by value Traverse from the END (i = size()-1 down to 0) — removing never affects unvisited lower indices
Traverse to read or modify values in place Enhanced for is fine, but do NOT add or remove (→ ConcurrentModificationException)

Example Code

import java.util.ArrayList;

ArrayList<Integer> nums = new ArrayList<Integer>();
nums.add(2); nums.add(5); nums.add(5); nums.add(8);

// Removing all 5s — CORRECT approach 1: traverse backward.
for (int i = nums.size() - 1; i >= 0; i--) {
    if (nums.get(i) == 5) {
        nums.remove(i);            // unvisited indices (0..i-1) are unaffected
    }
}
System.out.println(nums);          // [2, 8]

// CORRECT approach 2: adjust the loop counter when removing forward.
ArrayList<Integer> nums2 = new ArrayList<Integer>();
nums2.add(2); nums2.add(5); nums2.add(5); nums2.add(8);
for (int i = 0; i < nums2.size(); i++) {
    if (nums2.get(i) == 5) {
        nums2.remove(i);
        i--;                       // stay at this index to re-check what shifted here
    }
}
System.out.println(nums2);         // [2, 8]

// WRONG: adding or removing inside an enhanced for loop.
ArrayList<Integer> nums3 = new ArrayList<Integer>();
nums3.add(1); nums3.add(5); nums3.add(9);
// for (int v : nums3) { if (v == 5) nums3.remove(...); }
// -> ConcurrentModificationException at runtime

Topic 4.12 — 2D Array Traversals

Key Concepts

EK Concept Key Idea
4.12.A.1 Nested iteration Nested iteration statements are used to traverse and access all or an ordered sequence of elements in a 2D array. Nested loops can traverse in row-major order, column-major order, or a uniquely defined order. Row-major order traverses across each row; column-major order traverses down each column.
4.12.A.2 Enhanced for structure The outer loop of a nested enhanced for loop traverses the rows, so the enhanced for loop variable must be the type of each row — a 1D array. The inner loop traverses a single row, so its variable has the element type. Assigning a new value to the enhanced for loop variable does not change the value stored in the array.

Learning Objective 4.12.A: Develop code used to traverse the elements in a 2D array and determine the result of these traversals.

The two fundamental traversal orders:

Order Outer loop Inner loop Visits
Row-major row r column c across row 0, then row 1, then row 2 …
Column-major column c row r down column 0, then column 1, then column 2 … 
// Row-major:  outer loop = rows
for (int r = 0; r < grid.length; r++) {
    for (int c = 0; c < grid[r].length; c++) {
        process(grid[r][c]);
    }
}

// Column-major: outer loop = columns
for (int c = 0; c < grid[0].length; c++) {
    for (int r = 0; r < grid.length; r++) {
        process(grid[r][c]);
    }
}
Common mistakes
  • Using grid[0].length as the outer bound for a column-major loop over all columns is correct, but inside the inner loop use grid[r].length (or grid[0].length, since arrays are rectangular on the AP exam).
  • Forgetting that the outer loop variable must be the row in an enhanced for over a 2D array: for (int[] row : grid) — not for (int x : grid).

EK Concept Key Idea
4.14.A.1 Linear search Linear search algorithms are standard algorithms that check each element in order until the desired value is found or all elements in the array or ArrayList have been checked. Linear search algorithms can begin the search process from either end of the array or ArrayList.
4.14.A.2 Linear search on 2D arrays When applying linear search algorithms to 2D arrays, each row must be accessed, then linear search applied to each row of the 2D array.

Learning Objective 4.14.A: Develop code used for linear search algorithms to search for specific information in a collection and determine the results of executing a search.

Key facts about linear search:

  • Works on sorted or unsorted data.
  • Visits elements one by one, in order, until it finds a match or runs out of elements.
  • The average number of checks on an n-element list is about n/2; the worst case is n checks (target missing, or last element).
  • A common boolean variant stops and returns as soon as it finds a match; the index variant returns the position (or -1 if not found).
  • Can start from either end — front-to-back or back-to-front.
  • For a 2D array: linear-search each row, row by row.

Example Code

// Index version of linear search on an int[] (front to back).
public static int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) {
            return i;                 // found — return its index
        }
    }
    return -1;                        // not found
}

// Usage:
int[] data = {7, 2, 9, 4, 1, 5};
System.out.println(linearSearch(data, 9));   // 2
System.out.println(linearSearch(data, 10));  // -1

// Boolean variant that starts from the END (EK 4.14.A.1).
public static boolean containsFromEnd(int[] arr, int target) {
    for (int i = arr.length - 1; i >= 0; i--) {
        if (arr[i] == target) {
            return true;
        }
    }
    return false;
}

// Linear search on a 2D array: apply linear search to each row (EK 4.14.A.2).
public static boolean findInGrid(int[][] grid, int target) {
    for (int r = 0; r < grid.length; r++) {          // access each row
        for (int c = 0; c < grid[r].length; c++) {   // linear search within it
            if (grid[r][c] == target) {
                return true;
            }
        }
    }
    return false;
}

Topic 4.15 — Sorting Algorithms

Key Concepts

EK Concept Key Idea
4.15.A.1 Iterative sorts Selection sort and insertion sort are iterative sorting algorithms that can be used to sort elements in an array or ArrayList.
4.15.A.2 Selection sort Repeatedly selects the smallest (or largest) element from the unsorted portion of the list and swaps it into its correct (and final) position in the sorted portion of the list.
4.15.A.3 Insertion sort Inserts an element from the unsorted portion of a list into its correct (but not necessarily final) position in the sorted portion by shifting elements of the sorted portion to make room for the new element.

Learning Objective 4.15.A: Determine the result of executing each step of sorting algorithms to sort the elements of a collection.

The key difference in one sentence:

  • Selection sort: find the smallest remaining element and swap it to the front of the unsorted portion → each element lands in its final position immediately.
  • Insertion sort: take the next unsorted element and shift sorted elements right until it fits → the element’s position is correct so far but may not be final.

Selection sort trace on {29, 10, 14, 37, 13} (smallest-first version):

Start:   [29, 10, 14, 37, 13]
Pass 0:  smallest of [29,10,14,37,13] is 10 -> swap with index 0  -> [10, 29, 14, 37, 13]
Pass 1:  smallest of [29,14,37,13] is 13 -> swap with index 1     -> [10, 13, 14, 37, 29]
Pass 2:  smallest of [14,37,29] is 14 -> stays                      -> [10, 13, 14, 37, 29]
Pass 3:  smallest of [37,29] is 29 -> swap with index 3           -> [10, 13, 14, 29, 37]
Done.

Insertion sort trace on the same {29, 10, 14, 37, 13}:

Start:   [29] | 10, 14, 37, 13        (first element is the sorted portion)
Insert 10:  shift 29 right             -> [10, 29] | 14, 37, 13
Insert 14:  shift 29 right; 10 stays   -> [10, 14, 29] | 37, 13
Insert 37:  37 > 29, already in place  -> [10, 14, 29, 37] | 13
Insert 13:  shift 37, 29, 14 right     -> [10, 13, 14, 29, 37]

Example Code

// SELECTION SORT (ascending) — swap the smallest remaining into place.
int[] arr = {29, 10, 14, 37, 13};
for (int i = 0; i < arr.length - 1; i++) {
    int minIndex = i;
    for (int j = i + 1; j < arr.length; j++) {   // find smallest in unsorted part
        if (arr[j] < arr[minIndex]) {
            minIndex = j;
        }
    }
    // Swap arr[i] and arr[minIndex] — element i is now in its FINAL spot.
    int temp = arr[i];
    arr[i] = arr[minIndex];
    arr[minIndex] = temp;
}
// arr is now {10, 13, 14, 29, 37}

// INSERTION SORT (ascending) — insert each element into the sorted prefix.
int[] brr = {29, 10, 14, 37, 13};
for (int i = 1; i < brr.length; i++) {
    int value = brr[i];                    // the element to insert
    int j = i - 1;
    while (j >= 0 && brr[j] > value) {     // shift sorted elements right
        brr[j + 1] = brr[j];
        j--;
    }
    brr[j + 1] = value;                    // drop it into its spot
}
// brr is now {10, 13, 14, 29, 37}

Topic 4.16 — Recursion

Key Concepts

EK Concept Key Idea
4.16.A.1 Recursive method A recursive method is a method that calls itself. Recursive methods contain at least one base case, which halts the recursion, and at least one recursive call. Recursion is another form of repetition.
4.16.A.2 Own local variables Each recursive call has its own set of local variables, including the parameters. Parameter values capture the progress of a recursive process, much like loop control variable values capture the progress of a loop.
4.16.A.3 Recursion ↔ iteration Any recursive solution can be replicated through the use of an iterative approach and vice versa.

Learning Objective 4.16.A: Determine the result of executing recursive methods.

Out of Scope

Writing recursive code is NOT on the exam. The AP exam only asks you to determine the result of a given recursive method (trace its calls) or describe its behavior. You still need to understand how a base case and recursive calls work so you can trace them.

The anatomy of every recursive method:

public static int methodName(int n) {
    if (n == 0) {            // BASE CASE: stops the recursion
        return 0;
    }
    return methodName(n - 1); // RECURSIVE CALL: solve a smaller version
}

How to trace a recursive call: A call to a recursive method is just like a call to any method. When a method calls itself, the current call is paused (its local variables stay on the call stack), a brand-new call starts with fresh parameters, and — when the new call returns — the paused call resumes. EK 4.16.A.2 is the reason the same variable name can hold different values in each call.

Example Code

// Example 1: computing a factorial — n! = n * (n-1) * ... * 1
//   Trace factorial(4):
//   factorial(4) = 4 * factorial(3)
//                = 4 * (3 * factorial(2))
//                = 4 * (3 * (2 * factorial(1)))
//                = 4 * (3 * (2 * (1 * factorial(0))))
//                = 4 * (3 * (2 * (1 * 1)))   <- base case returns 1
//                = 24
public static int factorial(int n) {
    if (n == 0) {                 // base case
        return 1;
    }
    return n * factorial(n - 1);  // recursive call with a smaller argument
}

// Example 2: summing 1 + 2 + ... + n
public static int sum(int n) {
    if (n == 1) {                 // base case
        return 1;
    }
    return n + sum(n - 1);        // recursive call
}

// Example 3: counting down (prints, no return value)
public static void countDown(int n) {
    if (n == 0) {                 // base case
        System.out.println("Blast off!");
        return;
    }
    System.out.println(n);
    countDown(n - 1);             // recursive call
}

// Equivalent iterative version of sum (EK 4.16.A.3):
public static int sumIterative(int n) {
    int total = 0;
    for (int i = 1; i <= n; i++) {
        total += i;
    }
    return total;
}

Topic 4.17 — Recursive Searching and Sorting

Key Concepts

EK Concept Key Idea
4.17.A.1 Recursion on collections Recursion can be used to traverse String objects, arrays, and ArrayList objects.
4.17.B.1 Binary search Data must be in sorted order to use the binary search algorithm. Binary search starts at the middle of a sorted array or ArrayList and eliminates half of the array or ArrayList in each recursive call until the desired value is found or all elements have been eliminated.
4.17.B.2 Efficiency Binary search is typically more efficient than linear search.
4.17.B.3 Iterative or recursive The binary search algorithm can be written either iteratively or recursively.
4.17.C.1 Merge sort Merge sort is a recursive sorting algorithm that can be used to sort elements in an array or ArrayList.
4.17.C.2 Divide and conquer Merge sort repeatedly divides an array into smaller subarrays until each subarray is one element and then recursively merges the sorted subarrays back together in sorted order to form the final sorted array.

Learning Objective 4.17.A: Determine the result of executing recursive algorithms that use strings or collections.

Learning Objective 4.17.B: Determine the result of each iteration of a binary search algorithm used to search for information in a collection.

Learning Objective 4.17.C: Determine the result of each iteration of the merge sort algorithm when used to sort a collection.

Out of Scope

Search algorithms other than linear and binary search are outside the scope of the course and exam. Sorting algorithms other than selection, insertion, and merge sort are also out of scope. As with all recursion, you are tested on tracing these algorithms, not on writing recursive code.

Binary search rules to memorize:

  1. Precondition: the collection must already be in sorted order.
  2. Start with the whole range. Compare the middle element to the target:
    • Equal → found.
    • Target smaller → search only the left half (eliminate the right half).
    • Target larger → search only the right half (eliminate the left half).
  3. Repeat until found or the range is empty (low > high).
  4. Binary search is typically more efficient than linear search: linear search checks up to n elements; binary search eliminates half of the remaining elements each step (about log₂(n) checks).

Merge sort in three words: Split, sort, merge. Split the array in half repeatedly until each piece has one element, then merge pieces back together in sorted order.

Example Code

// BINARY SEARCH — recursive version (shown for tracing purposes).
// Precondition: arr is sorted ascending. Returns the index of target, or -1.
public static int binarySearch(int[] arr, int target, int low, int high) {
    if (low > high) {              // range is empty — target not present
        return -1;
    }
    int mid = (low + high) / 2;
    if (arr[mid] == target) {
        return mid;
    } else if (arr[mid] > target) {
        return binarySearch(arr, target, low, mid - 1);   // search left half
    } else {
        return binarySearch(arr, target, mid + 1, high);  // search right half
    }
}

// Trace for arr = {1, 3, 5, 7, 9, 11, 13}, target = 9:
//   low=0 high=6 mid=3 -> arr[3]=7 < 9 -> search right: low=4
//   low=4 high=6 mid=5 -> arr[5]=11 > 9 -> search left: high=4
//   low=4 high=4 mid=4 -> arr[4]=9 -> FOUND at index 4

// MERGE SORT — split phase and merge phase (shown for tracing purposes).
public static void mergeSort(int[] arr, int low, int high) {
    if (low < high) {                                  // more than 1 element
        int mid = (low + high) / 2;
        mergeSort(arr, low, mid);      // split left half
        mergeSort(arr, mid + 1, high); // split right half
        merge(arr, low, mid, high);    // merge the two sorted halves
    }
    // base case: low == high means a single element — already sorted
}
// The merge step compares the front of each sorted half and copies the
// smaller value into a temporary array, then copies the result back.

That decision is only valid if the array is ordered — e.g., searching {6, 4, 2, 8} for 2: the middle element is 4, and since 4 > 2 the search eliminates the right half {2, 8}, incorrectly discarding the very value it is looking for. The data must be sorted first. [2]

(b)

  • low=0, high=3, mid=1 → arr[1]=4, 4 < 5, search right: low=2
  • low=2, high=3, mid=2 → arr[2]=6, 6 > 5, search left: high=1
  • Now low=2 > high=1, the range is empty, so the search stops and returns -1 (not found). [3]

Merge sort is applied to {5, 2, 8, 1, 9}.

✏️ Exercise 4.17.5 — Choosing a Search Algorithm (3 marks)

A programmer has two arrays to search and must choose linear or binary search.

(a) Array A has 1,000,000 numbers in random order. Which search must be used, and why? [2]
(b) Array B has 1,000,000 numbers already sorted. Which search is typically more efficient, and why? [1]

📖 参考答案 | Reference Answer

(a) Linear search. Binary search requires sorted data (its precondition), and Array A is not sorted, so only linear search can be guaranteed to find a value correctly. [2]

(b) Binary search — it eliminates half of the remaining elements at each step, so it is typically more efficient than linear search, which may check every element. [1]
