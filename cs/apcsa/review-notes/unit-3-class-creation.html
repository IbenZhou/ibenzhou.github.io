Unit 3 — Class Creation: Review Notes

Syllabus: AP Computer Science A — Course and Exam Description, Effective Fall 2025
Exam Weight: 10–18% of AP Exam | Class Periods: ~20–22
Topics: 3.1–3.9
AP Classroom: Progress Checks — Part 1 (3.1–3.4) ~12 MCQ; Part 2 (3.5–3.9) ~15 MCQ + 2 FRQ (Class Design)

Overview

This unit pulls together information from Units 1 and 2 to create new, user-defined reference data types in the form of classes. The ability to accurately model real-world entities in a computer program is a large part of what makes computer science so powerful. By designing their own classes, programmers are not limited to the existing classes provided in the Java libraries and can represent their own ideas. This unit focuses on identifying the appropriate attributes and behaviors of real-world entities and organizing these into classes and their corresponding methods. It also addresses the legal and ethical concerns that come with creating programs and the responsibilities of programmers.

In this unit you will learn to:

  • Design and implement a class based on program specifications, including the class header, private instance variables, constructors, and methods.
  • Identify the attributes (data) that define an object of a class and the behaviors (methods) that define what an object of a class does.
  • Use access modifiers (public and private) to control access to classes, data, constructors, and methods.
  • Write constructors that set the initial state of an object and understand default values.
  • Write methods that use primitive values and object references, including accessor and mutator methods.
  • Use class (static) variables and class (static) methods.
  • Explain scope and access rules for local variables, parameters, and instance variables.
  • Use the this keyword to write self-referencing expressions.
  • Explain the social, economic, cultural, and ethical implications of computing systems.
💡 Exam Tip
  • Access modifiers matter on the FRQ: On Question 2 (Class Design), instance variables should be private, while constructors and the methods the specification requires are public. Private helper methods are allowed.
  • Constructor vs. method: A constructor has the same name as the class, has no return type (not even void), and is called with new. A method has a return type and is called with a dot.
  • Instance vs. static: Instance variables/methods belong to each object and are accessed through a reference; class (static) variables/methods belong to the class and are accessed through the class name. Only static members can be used inside a class method without an object reference.
  • this and shadowing: this refers to the current object in an instance method or constructor. Use it to disambiguate a parameter with the same name as an instance variable (this.balance = balance). Class methods have no this reference.
  • Question 2 (Class Design) provides a scenario and a specification table describing methods and their behavior. Read the table carefully, match method signatures exactly, and follow the preconditions described.

Topic 3.1 — Abstraction and Program Design

Key Concepts

EK Concept Key Idea
3.1.A.1 Abstraction The process of reducing complexity by focusing on the main idea. By hiding details irrelevant to the question at hand and bringing together related, useful details, abstraction reduces complexity and lets you focus on the idea.
3.1.A.2 Data abstraction A separation between the abstract properties of a data type and the concrete details of its representation. Data abstraction manages complexity by giving data a name without referencing the specific details of its representation. Data can be a single variable or a collection of data, such as in a class or a set of data.
3.1.A.3 Attribute, instance variable, class variable An attribute is a type of data abstraction defined in a class outside any method or constructor. An instance variable’s value is unique to each instance of the class. A class variable is shared by all instances of the class.
3.1.A.4 Procedural abstraction, method decomposition Procedural abstraction gives a name to a process so a method can be used knowing only what it does, not how it does it. Method decomposition breaks larger behaviors into smaller behaviors implemented as methods. Extracting shared features generalizes functionality instead of duplicating code, enabling code reuse.
3.1.A.5 Parameters generalize procedures Using parameters allows procedures to be generalized so they can be reused with a range of input values or arguments.
3.1.A.6 Changing method internals Using procedural abstraction lets programmers change the internals of a method (to make it faster, more efficient, use less storage, etc.) without notifying method users, as long as the method signature and what the method does is preserved.
3.1.A.7 Design before implementation Prior to implementing a class, it is helpful to design each class, including its attributes and behaviors. This design can be represented using natural language or diagrams (e.g., UML).

Learning Objective 3.1.A: Represent the design of a program by using natural language or creating diagrams that indicate the classes in the program and the data and procedural abstractions found in each class by including all attributes and behaviors.

Design process: Think about a real-world entity → pick the nouns (attributes) and the verbs (behaviors) → group them into a class → sketch the design in natural language or a UML diagram → then write the Java code.

Example Code

// Design step 1: Identify attributes and behaviors of a "Car"
// Attributes (data/nouns):   make, model, fuel (double)
// Behaviors (methods/verbs): drive(), refuel(), getFuel()

// Design step 2: Represent the design in natural language / UML
// Car
// ------
// - make : String
// - model : String
// - fuel : double
// ------
// + drive(double miles) : void
// + refuel(double gallons) : void
// + getFuel() : double

// Design step 3: Implement the class
public class Car {
    private String make;      // data abstraction: a named attribute
    private String model;
    private double fuel;      // in gallons

    public Car(String carMake, String carModel, double startFuel) {
        make = carMake;
        model = carModel;
        fuel = startFuel;
    }

    // Procedural abstraction: we know WHAT drive does, not HOW it works
    public void drive(double miles) {
        fuel -= miles / 20.0;   // assume 20 miles per gallon
    }

    public void refuel(double gallons) {
        fuel += gallons;
    }

    public double getFuel() {
        return fuel;
    }
}

✏️ Exercise 3.1.3 — Benefits of Procedural Abstraction (3 marks)

A programmer wrote one long 80-line method to play a game, and another programmer broke the same task into five small methods.

Topic 3.2 — Impact of Program Design

Key Concepts

EK Concept Key Idea
3.2.A.1 System reliability Refers to the program being able to perform its tasks as expected under stated conditions without failure. Programmers should make an effort to maximize system reliability by testing the program with a variety of conditions.
3.2.A.2 Impacts of programs The creation of programs has impacts on society, the economy, and culture. These impacts can be both beneficial and harmful. Programs meant to fill a need or solve a problem can have unintended harmful effects beyond their intended use.
3.2.A.3 Legal issues and intellectual property Programmers often reuse code written by others and published as open source and free to use. Incorporating code that is not published as open source requires the programmer to obtain permission and often to purchase the code before integrating it into their program.

Learning Objective 3.2.A: Explain the social and ethical implications of computing systems.

Key ideas to internalize for the exam:

  • Reliability requires testing: A reliable system performs its tasks under stated conditions without failure. Testing with a variety of conditions (normal, boundary, and invalid inputs) helps catch failures early.
  • Dual nature of impact: A program designed to solve a problem can also cause unintended harm. Consider who is affected, how, and whether the effect is beneficial or harmful to society, the economy, and culture.
  • Code reuse and licenses: Open-source code is free to use. Code that is not open source must be licensed — you need permission and often must pay before integrating it.
  • Responsible programming: A responsible programmer tests thoroughly, respects licenses and intellectual property, and considers the broader consequences of their code.

Example Code

// Reliability example: test a method with a variety of conditions
public class Grades {
    private double average;

    // Precondition: scores is not null and has at least one element
    public void computeAverage(int[] scores) {
        double sum = 0;
        for (int s : scores) {
            sum += s;
        }
        average = sum / scores.length;
    }

    public double getAverage() {
        return average;
    }

    public static void main(String[] args) {
        Grades g = new Grades();

        // Test variety of conditions to maximize system reliability:
        g.computeAverage(new int[] {90, 85, 95});       // normal case
        g.computeAverage(new int[] {100});              // single element
        g.computeAverage(new int[] {0, 0, 0});          // boundary (all zeros)
        g.computeAverage(new int[] {90, -5, 100});      // unusual data
        System.out.println(g.getAverage());
    }
}
✏️ Exercise 3.2.1 — Testing for System Reliability (4 marks)

A program tracks a bank account balance. It has a method withdraw(double amount) that subtracts the amount from the balance.

(a) State two different conditions (sets of input values) the programmer should test, other than a normal withdrawal, and explain why each is important. [2]
(b) Explain why testing with a variety of conditions helps maximize system reliability. [2]

📖 参考答案 | Reference Answer

(a) Accept, for example: (1) withdrawing an amount larger than the balance (boundary/invalid case — ensures the program handles overdrafts without producing a negative balance or crashing); (2) withdrawing exactly 0 or exactly the entire balance (boundary case — ensures exact limits behave as expected); (3) withdrawing a negative amount (invalid input — ensures the program rejects nonsensical input). Any two such conditions with a reason are acceptable. [2]

(b) System reliability means the program performs its tasks as expected under stated conditions without failure. Testing with a variety of conditions — normal, boundary, and invalid inputs — reveals failures before the program is used, so the programmer can fix them and the program behaves correctly in the situations it will actually face. [2]

Topic 3.3 — Anatomy of a Class

Key Concepts

EK Concept Key Idea
3.3.A.1 Data encapsulation A technique in which the implementation details of a class are kept hidden from external classes. The keyword private restricts access to the declaring class, while public allows access from classes outside the declaring class.
3.3.A.2 Class header In this course, classes are always designated public and are declared with the keyword class (e.g., public class BankAccount).
3.3.A.3 Constructors In this course, constructors are always designated public.
3.3.A.4 Instance variables Instance variables belong to the object, and each object has its own copy of the variable.
3.3.A.5 Private attributes Access to attributes should be kept internal to the class to accomplish encapsulation. It is good programming practice to designate instance variables as private unless the class specification states otherwise.
3.3.A.6 Method access Access to behaviors can be internal or external to the class. public methods can be accessed internally or externally; private methods can only be accessed internally to the class.

Learning Objective 3.3.A: Develop code to designate access and visibility constraints to classes, data, constructors, and methods.

The parts of a class, in order:

  1. Class header — public class ClassName
  2. Instance variables (attributes) — declared private, before any constructor or method
  3. Constructors — public, same name as the class, set the initial state
  4. Methods — behaviors; can be public or private

We begin building a coherent BankAccount example that will be extended in Topics 3.4–3.9.

Example Code

// Topic 3.3: The skeleton of a class — header, attributes, constructor, methods
public class BankAccount {                     // 1. class header (always public)

    private String owner;                      // 2. instance variables: private,
    private double balance;                    //    one copy per object

    public BankAccount(String accountOwner) {  // 3. constructor (always public)
        owner = accountOwner;
        balance = 0.0;
    }

    public double getBalance() {               // 4a. public method: callable from
        return balance;                        //     inside or outside the class
    }

    private void checkMinimum() {              // 4b. private method: only callable
        // internal helper — hidden from other classes
        if (balance < 25.0) {
            System.out.println("Low balance warning");
        }
    }
}



// Encapsulation in action: the data is private, behavior is public
public class BankTester {
    public static void main(String[] args) {
        BankAccount a = new BankAccount("Alex");
        System.out.println(a.getBalance());    // OK: public method, external access

        // System.out.println(a.balance);      // ERROR: balance is private —
                                               // cannot be accessed from outside
    }
}

✏️ Exercise 3.3.2 — Encapsulation and Access (4 marks)

(a) Define data encapsulation and explain why instance variables are made private in this course. [2]
(b) A method is designated private. Who can call it, and who cannot? Give an example use of a private method. [2]

📖 参考答案 | Reference Answer

Topic 3.4 — Constructors

Key Concepts

EK Concept Key Idea
3.4.A.1 Object state, has-a An object’s state refers to its attributes and their values at a given time and is defined by instance variables belonging to the object. This defines a has-a relationship between the object and its instance variables.
3.4.A.2 Constructor Used to set the initial state of an object, including initial values for all instance variables. When a constructor is called, memory is allocated for the object and the associated object reference is returned. Constructor parameters, if specified, provide data to initialize instance variables.
3.4.A.3 Mutable object parameters When a mutable object is a constructor parameter, the instance variable should be initialized with a copy of the referenced object. This prevents methods from modifying the state of the original object.
3.4.A.4 Default constructor When no constructor is written, Java provides a no-parameter constructor and the instance variables are set to default values according to the data type.
3.4.A.5 Default values Default value of int is 0; double is 0.0; boolean is false; a reference type is null.

Learning Objective 3.4.A: Develop code to declare instance variables for the attributes to be initialized in the body of the constructors of a class.

Rules of constructors:

  • A constructor has the same name as the class and no return type (not even void).
  • Constructors are always public in this course.
  • A constructor should initialize all instance variables.
  • Constructors are invoked with new; they return the object reference.
  • If you write any constructor, Java does not provide the default constructor.

Example Code

// Topic 3.4: BankAccount with overloaded constructors
public class BankAccount {
    private String owner;
    private double balance;

    // Constructor 1: initializes both attributes from parameters
    public BankAccount(String accountOwner, double initialDeposit) {
        owner = accountOwner;
        balance = initialDeposit;
    }

    // Constructor 2: overloaded — only owner given, balance starts at 0.0
    public BankAccount(String accountOwner) {
        owner = accountOwner;
        balance = 0.0;              // 0.0 is also the default value of double
    }
}

// Usage
BankAccount a = new BankAccount("Alex", 500.0);  // state: owner "Alex", balance 500.0
BankAccount b = new BankAccount("Bella");        // state: owner "Bella", balance 0.0



// Topic 3.4: Default values — when NO constructor is written
public class Point {
    private int x;      // default value 0
    private double y;   // default value 0.0
    private boolean on; // default value false
    private String tag; // default value null
    // No constructor written -> Java provides a no-parameter default constructor.
}

public class PointTester {
    public static void main(String[] args) {
        Point p = new Point();   // default constructor is used
        // p.x == 0, p.y == 0.0, p.on == false, p.tag == null
    }
}

✏️ Exercise 3.4.3 — Mutable Object Parameter (4 marks)

A BankAccount class stores the customer’s address as a String[] (mutable). The constructor receives String[] addr.

(a) Explain the danger of assigning address = addr; directly, using EK 3.4.A.3. [2]
(b) Write the constructor body that correctly initializes the address instance variable with a copy of the referenced array. [2]

📖 参考答案 | Reference Answer

(a) If address = addr; is used, the instance variable holds a reference to the same array as the caller’s. Because an array is mutable, a method could change an element of the array, which would modify the original object’s array too — changing the state of the original object that was passed in. The instance variable should be initialized with a copy so the account’s data cannot be altered from outside. [2]

(b)

public BankAccount(String owner, String[] addr) {
    this.owner = owner;
    address = new String[addr.length];
    for (int i = 0; i < addr.length; i++) {
        address[i] = addr[i];
    }
}

This copies the contents into a new array, so the instance variable does not hold a reference to the original object. (2 marks)

✏️ Exercise 3.4.4 — State and Has-a Relationship (3 marks)

(a) The state of an object refers to its attributes and their values at a given time; it is defined by the instance variables belonging to the object. Topic 3.5 — Methods: How to Write Them

Key Concepts

EK Concept Key Idea
3.S.A.1 void methods A void method does not return a value. Its header contains the keyword void before the method name.
3.S.A.2 Non-void methods A non-void method returns a single value. Its header includes the return type in place of the keyword void.
3.S.A.3 Return by value In non-void methods, a return expression compatible with the return type is evaluated, and the value is returned (return by value).
3.S.A.4 The return keyword Returns the flow of control to the point where the method or constructor was called. Any code sequentially after a return statement never executes. A return inside a selection or iteration statement halts the statement and exits the method or constructor.
3.S.A.5 Accessor method Allows objects of other classes to obtain a copy of the value of instance variables or class variables. An accessor is a non-void method.
3.S.A.6 Mutator (modifier) method Changes the values of instance variables or class variables. A mutator is often a void method.
3.S.A.7 Methods with parameters Receive values through those parameters and use those values in accomplishing the method’s task.
3.S.A.8 Primitive arguments When an argument is a primitive value, the parameter is initialized with a copy of that value. Changes to the parameter have no effect on the corresponding argument.

Learning Objective 3.S.A: Develop code to define behaviors of an object through methods written in a class using primitive values and determine the result of calling these methods.

Anatomy of a method:

accessModifier  returnType  methodName(parameterList)  {
    method body
}
public         double      getBalance()                { ... }
public         void        deposit(double amount)      { ... }

Example Code

// Topic 3.5: BankAccount methods — accessors, mutators, and void vs non-void
public class BankAccount {
    private String owner;
    private double balance;

    public BankAccount(String accountOwner, double initialDeposit) {
        owner = accountOwner;
        balance = initialDeposit;
    }

    // Accessor (non-void): returns a copy of the balance value
    public double getBalance() {
        return balance;
    }

    // Accessor (non-void): returns the owner
    public String getOwner() {
        return owner;
    }

    // Mutator (void): changes state, returns nothing
    public void deposit(double amount) {
        balance += amount;
    }

    // Mutator (void): returns true/false via a boolean result — note the early return
    public boolean withdraw(double amount) {
        if (amount > balance) {
            return false;      // return halts the method here
        }
        balance -= amount;

Topic 3.6 — Methods: Passing and Returning References of an Object

Key Concepts

EK Concept Key Idea
3.6.A.1 Object references as arguments When an argument is an object reference, the parameter is initialized with a copy of that reference — it does not create a new independent copy of the object. If the parameter refers to a mutable object, the method or constructor can use the reference to alter the state of that object. It is good programming practice not to modify mutable objects passed as parameters unless the specification requires it.
3.6.A.2 Returning object references When the return expression evaluates to an object reference, the reference is returned, not a reference to a new copy of the object.
3.6.A.3 Access through a parameter Methods cannot access the private data and methods of a parameter that holds a reference to an object unless the parameter is the same type as the method’s enclosing class.

Learning Objective 3.6.A: Develop code to define behaviors of an object through methods written in a class using object references and determine the result of calling these methods.

Key idea — the reference is the prize: passing an object to a method copies the reference (the “address”), not the object. Two references to the same mutable object mean changes through one are visible through the other (aliasing).

Example Code

// Topic 3.6: Passing and returning object references
public class BankAccount {
    private String owner;
    private double balance;

    public BankAccount(String accountOwner, double initialDeposit) {
        owner = accountOwner;
        balance = initialDeposit;
    }

    public double getBalance() {
        return balance;
    }

    public void deposit(double amount) {
        balance += amount;
    }

    // Parameter `other` holds a copy of the reference to the SAME object.
    public void transferTo(BankAccount other, double amount) {
        if (amount <= balance) {
            this.balance -= amount;
            other.balance += amount;   // OK: same class, so private data is visible
        }
    }

    // Returns the reference to the receiver itself (a "self-reference").
    public BankAccount getSelf() {
        return this;                   // returns the reference, not a copy
    }
}

public class ReferenceTester {
    public static void main(String[] args) {
        BankAccount a = new BankAccount("Alex", 500.0);
        BankAccount b = new BankAccount("Bella", 100.0);
        a.transferTo(b, 150.0);
        System.out.println(a.getBalance());   // 350.0
        System.out.println(b.getBalance());   // 250.0

        BankAccount alias = a.getSelf();      // alias and a refer to the SAME object
        alias.deposit(50.0);
        System.out.println(a.getBalance());   // 400.0 — same object was changed!
    }
}



// Aliasing: two references, one object (EK 3.6.A.1)
public class AliasDemo {
    public static void main(String[] args) {
        BankAccount x = new BankAccount("Casey", 200.0);
        BankAccount y = x;              // y now refers to the SAME object as x
        y.deposit(100.0);
        System.out.println(x.getBalance());   // 300.0 — x "sees" the change
    }
}

Topic 3.7 — Class Variables and Methods

Key Concepts

EK Concept Key Idea
3.7.A.1 Class methods and instance members Class methods cannot access or change the values of instance variables or call instance methods without being passed an instance of the class via a parameter.
3.7.A.2 Class methods and class members Class methods can access or change the values of class variables and can call other class methods.
3.7.B.1 Class variables (static) Class variables belong to the class; all objects of the class share a single copy. They are designated with the keyword static before the variable type.
3.7.B.2 Accessing public class variables Class variables that are public are accessed outside the class using the class name and the dot operator, since they are associated with the class, not with objects.
3.7.B.3 final variables When a variable is declared final, its value cannot be modified.

Learning Objectives:

  • 3.7.A: Develop code to define behaviors of a class through class methods.
  • 3.7.B: Develop code to declare the class variables that belong to the class.

Rules of thumb:

  • static = belongs to the class, not to any one object. One shared copy exists.
  • A class (static) method can only touch instance variables/methods if it is passed an instance as a parameter.
  • public static variables are accessed as ClassName.variableName.
  • static final = a named constant, e.g., public static final double MIN_BALANCE = 0.0;.

Example Code

// Topic 3.7: Class variables and class methods in BankAccount
public class BankAccount {
    private static int totalAccounts = 0;          // shared by ALL BankAccount objects
    public static final double MIN_BALANCE = 25.0; // named constant (cannot be modified)

    private String owner;
    private double balance;

    public BankAccount(String accountOwner, double initialDeposit) {
        owner = accountOwner;
        balance = initialDeposit;
        totalAccounts++;                           // every new object increments the shared count
    }

    // Class method: can access class variables and other class methods
    public static int getTotalAccounts() {
        return totalAccounts;
    }

    // Class method: may access an instance's private data ONLY via a passed-in instance
    public static void printBalance(BankAccount acc) {
        System.out.println(acc.owner + ": " + acc.balance);  // OK — acc is provided
    }

    // Instance method: may access instance and class members freely
    public double getBalance() {
        return balance;
    }
}

public class AccountCounter {
    public static void main(String[] args) {
        BankAccount a = new BankAccount("Alex", 500.0);
        BankAccount b = new BankAccount("Bella", 100.0);

        // Class variable/method accessed through the CLASS NAME, not an object
        System.out.println(BankAccount.getTotalAccounts());   // 2
        System.out.println(BankAccount.MIN_BALANCE);          // 25.0

        BankAccount.printBalance(a);                          // Alex: 500.0
    }
}

Topic 3.8 — Scope and Access

Key Concepts

EK Concept Key Idea
3.8.A.1 Local variables Local variables are declared in the headers or bodies of blocks of code. They can only be accessed in the block in which they are declared. Since constructors and methods are blocks of code, parameters to constructors or methods are also considered local variables. They may only be used within the constructor or method and cannot be declared public or private.
3.8.A.2 Shadowing When there is a local variable or parameter with the same name as an instance variable, the variable name refers to the local variable instead of the instance variable within the body of the constructor or method.

Learning Objective 3.8.A: Explain where variables can be used in the code.

Scope rules to remember:

  • Instance variable — accessible anywhere inside the class (in any constructor or method).
  • Local variable / parameter — accessible only inside its block (its constructor or method).
  • No access modifiers on local variables — public/private only apply to class-level members.
  • Shadowing — a parameter or local variable with the same name as an instance variable “hides” it inside that block. Use this (Topic 3.9) to refer to the instance variable.

Example Code

// Topic 3.8: Scope — where each variable may be used
public class BankAccount {
    private String owner;   // instance variable: usable anywhere in the class
    private double balance;

    public BankAccount(String owner, double initialDeposit) {
        // The parameter `owner` SHADOWS the instance variable `owner`.
        owner = owner;      // BUG: both sides are the parameter — the instance
                            // variable is never set! (Fixed with `this` in 3.9)
        balance = initialDeposit;
    }

    public void deposit(double amount) {          // amount is a local parameter
        double fee = 0.5;                         // local variable in this block
        balance += amount - fee;
        // System.out.println(owner);             // OK — instance variable in scope
    }

    public double getBalance() {
        return balance;
        // amount and fee are NOT accessible here — they are out of scope.
    }
}

            System.out.println(squared);

        // System.out.println(i);        // ERROR: out of scope

Topic 3.9 — this Keyword

Key Concepts

EK Concept Key Idea
3.9.A.1 this as a reference to the current object Within an instance method or a constructor, the keyword this acts as a special variable that holds a reference to the current object — the object whose method or constructor is being called.
3.9.A.2 Passing this The keyword this can be used to pass the current object as an argument in a method call.
3.9.A.3 No this in class methods Class methods do not have a this reference.

Learning Objective 3.9.A: Develop code for expressions that are self-referencing and determine the result of these expressions.

Three main uses of this:

  1. Disambiguate parameter shadowing — this.balance = balance; (the this.balance is the instance variable; balance is the parameter).
  2. Pass the current object as an argument — register(this); inside an instance method hands the current object to another method.
  3. Return the current object — return this; returns the reference to the current object.
  4. Call another constructor — this(...) invokes a sibling constructor of the same class (commonly used, e.g., this(owner, 0.0);).

Example Code

// Topic 3.9: this disambiguates shadowed names and refers to the current object
public class BankAccount {
    private String owner;
    private double balance;

    // Full constructor
    public BankAccount(String owner, double balance) {
        this.owner = owner;        // this.owner = instance variable; owner = parameter
        this.balance = balance;
    }

    // Constructor chaining with this(...) — delegates to the full constructor
    public BankAccount(String owner) {
        this(owner, 0.0);
    }

    // this as the current object: pass self to a class method
    public void printStatement() {
        BankAccount.printSummary(this);   // passes the current object as an argument
    }

    public double getBalance() {
        return this.balance;             // this is optional here, but explicit
    }

    // Class method: receives the object via the parameter (no this available)
    public static void printSummary(BankAccount acc) {
        System.out.println(acc.owner + ": " + acc.balance);
    }
}

        BankAccount a = new BankAccount("Alex", 500.0);

        b.printStatement();                          // Bella: 0.0
    }
}

✏️ Exercise 3.9.2 — Passing `this` as an Argument (4 marks)

A BankAccount has a class method public static boolean canTransfer(BankAccount from, BankAccount to, double amount).

(a) Write an instance method transfer(double amount, BankAccount to) that uses this to pass the current object as the “from” account in a call to canTransfer. [2]
(b) Explain why passing this is necessary here, referencing EK 3.9.A.2. [2]

📖 参考答案 | Reference Answer

(a)

public void transfer(double amount, BankAccount to) {
    if (BankAccount.canTransfer(this, to, amount)) {
        this.balance -= amount;
        to.balance += amount;
    }
}

[2]

(b) The class method canTransfer needs the current object to compare with to and amount. The keyword this holds a reference to the current object — the object whose method is being called — so this is passed as the argument to hand that object to the class method. This is exactly the use described in EK 3.9.A.2. [2]

public static void f1() { System.out.println(this); }                 // segment 1

(a)

public Student(String name, int grade) {

}

✏️ Exercise 3.9.4 — Is `this` Needed? (3 marks)

(a) State whether this is required in return balance; inside an accessor, and what it would be if written as return this.balance;. [1]
(b) A constructor has no parameters named the same as instance variables. Is this required to initialize the instance variables? Explain. [1]
© Why does this(...) constructor chaining save work, and what restriction must the chained call satisfy? [1]

📖 参考答案 | Reference Answer

(a) this is optional when there is no shadowing — return balance; returns the instance variable. return this.balance; is the fully explicit form, referencing the current object’s instance variable. [1]

(b) No. this is only needed to disambiguate when a parameter or local variable has the same name as an instance variable. Without shadowing, owner = name; already refers to the instance variable. [1]

© Constructor chaining lets one constructor reuse the initialization logic of another instead of duplicating code. The call this(args) must be the first statement in the constructor and must match an existing constructor’s signature. [1]
