Circuit switching

What is circuit switching?

  • Circuit switching sets up a dedicated channel (circuit) between sender and receiver that lasts for the whole connection — the line is effectively tied up until the call ends
  • This is how a traditional telephone call works
  • Every message follows the same single route, in the order it was sent, as a continuous stream
  • Transmission is usually bidirectional
  • There are three stages in every circuit-switched connection:
    1. Establish the circuit between sender and receiver
    2. Transfer the data (analogue or digital, usually bi-directional)
    3. Terminate the connection when the transfer is complete (the circuit is closed / released at the end)

Advantages

  • The circuit is dedicated to that single transmission only
  • The whole bandwidth is available to the user, giving a steady / fixed / high data transfer rate
  • Data transfer rate is constant and predictable, because the whole bandwidth of the circuit is reserved for the connection
  • Data (frames) arrive in the same order they were sent — no need to reassemble and no time lost reordering
  • Data cannot get lost — all of it follows one route in sequence
  • No waiting time at switches and no intermediate delays once the circuit is established
  • Simple method of data transfer
  • Suitable for long, continuous transmission
  • Works better than packet switching for real-time applications (voice, video, video streaming)

Disadvantages

  • Not flexible — empty frames may still be sent, and only a single dedicated line is used
  • Nobody else can use the circuit, even when it is idle — the circuit is always there whether or not it is being used
  • Bandwidth cannot be shared, so system resources are underutilised / inefficient and bandwidth may be wasted
  • High / whole bandwidth is required, and establishing a dedicated path for each connection can have cost implications
  • If there is a failure on the dedicated line there is no alternative route — the call is dropped and must be re-established
  • The time needed to establish the link can be long, before any data moves
  • Reduced security — all data travels along a single path, so it can be intercepted
  • Scalability is difficult — more users require more physical paths

Where it is used

  • Public telephone networks (PSTN)
  • Private telephone networks
  • Private data networks
  • Any situation where a dedicated path must be sustained throughout the call, where the whole bandwidth is required, or where real-time communication is needed (standard voice communications, video streaming)

Packet switching

What is packetising?

  • Packetising is the process of dividing a large message into smaller, equal-sized, manageable units called packets
  • Each packet can be transmitted individually across a network

Structure of a packet

  • Each packet typically contains:
    • Header – contains control information such as:
      • Source IP address – who sent the packet
      • Destination IP address – where it’s going
      • Sequence number / packet number – used to reassemble packets in the correct order
      • Hop count – how many more routers the packet may pass through
      • Protocol – e.g. TCP or UDP
      • Packet length – the size of the packet
      • Checksum – used for error checking
    • Payload – the actual data being sent
    • Footer (trailer) – may include extra error-checking or control information

What is packet switching?

  • Packet switching is a communication method where data is broken into packets and sent across a shared network
  • Each packet may take a different path to the destination and is reassembled on arrival
  • Each packet follows its own path; the route chosen depends on the congestion — the number of datagrams waiting to be processed at each node (router) — and the optimum / shortest available path is selected using a routing table
  • Packets can therefore reach the destination in a different order from the one in which they were sent

Advantages

  • No need to tie up a communication line — the path is available to multiple users and bandwidth is shared
  • Efficient use of network bandwidth — capacity is shared, not reserved
  • Resilience: if the network changes, a router can detect this and send the data another way
  • Accuracy: ensures accurate delivery of the message
  • Completeness: missing packets can be easily detected and a re-send request sent, so the message arrives complete
  • Failed or faulty lines are overcome by re-routing packets, and individual lost / damaged packets can be re-sent (so packets are more likely to arrive)
  • Easy to expand traffic usage — highly scalable
  • Users are charged only for the duration of the connectivity, not the distance
  • High data transmission rates are possible
  • Always uses digital networks, so digital data is transmitted directly
  • Good security — packets can be hashed and sent by different routes, so a message is harder to intercept

Disadvantages

  • The protocols are more complex than those for circuit switching — a complex algorithm is required to function
  • If a packet is lost, the sender must re-send it, which wastes time
  • Time delays to correct errors / while packets are reassembled at the destination / because bandwidth is shared
  • Does not work well with real-time data streams (VoIP, video calls) — unsuitable for real-time transmission applications
  • The channel has to share its bandwidth with other packets
  • Needs large amounts of RAM to handle large volumes of data

Lost packets and error checking

  • Left alone, a lost packet can keep ‘bouncing’ between routers and never arrive — eventually the network clogs up
  • Hop count: each packet may only be forwarded a finite number of times; the hop number decreases by 1 at every router, and the packet is deleted when it reaches 0
  • Checksum: calculated and added to the header by the sender, recalculated at the destination; if the two values differ, a request is made to re-send the packet
  • Priority value: sometimes added to the header; a high priority value selects a higher-priority queue at the router

The function of a router

What a router does

  • A router connects different networks and forwards packets towards their destination (a network-layer device)
  • When a packet arrives, the router:
    1. Examines the packet header — specifically reads the IP address of the destination
    2. Uses its routing table to find information about available hops / netmask / gateway used / adjacent routers / the status of the routers along the route
    3. Determines the next hop / optimum (best) route to the destination network
    4. Sends the packet on its next hop out of the correct interface
    5. Manages the hop counter — it is reduced by 1 every time the packet passes a router (and replaces the MAC address in the frame header with that of the next router)
  • The IP addresses stay the same from end to end — only the MAC address changes at every hop
  • A router discards a packet when:
    • no route in the table matches the destination address, or
    • the hop count has already reached 0

Routing tables

  • A routing table contains the information needed to forward a packet along the shortest or best route to its destination
  • A routing table includes:
    • Number of hops / available hops to the destination
    • MAC address of the next router the packet will be forwarded to
    • Metrics — a cost assigned to each route, so the most efficient path can be found
    • Network destination (network ID) or pathway
    • Gateway — the next hop through which the target network can be reached
    • Netmask — used to generate the network ID
    • Interface — which locally available interface reaches that gateway
    • Status of the routers / routes along the route, and adjacent routers

Circuit switching vs packet switching

Feature Circuit switching Packet switching
Route Must be set up before transmission begins No route is set up in advance — data transfer starts straight away
Path A dedicated transmission path is required Path is shared with other users’ packets
Addressing Each data unit knows the entire path address Each data unit only knows the final address (routers decide intermediate paths)
Routing of data Every frame follows the same route Each packet may take a different route
Form of data Message remains intact / a continuous stream Data is split into packets
Order of arrival Always in the correct order, no reassembly needed May arrive out of order — reassembled at the destination
Bandwidth The whole bandwidth of the channel is used (constant high bandwidth) Bandwidth is shared between packets (variable bandwidth)
Idle time Bandwidth is wasted when nothing is being sent Idle capacity is used by other packets
Efficiency Low — resources are tied up, underutilised for each communication High — uses bandwidth as needed
Reliability If the path fails the call is dropped; the whole transmission must be resent Packets are re-routed / individual packets re-sent around a failure
Security Less secure — single path can be intercepted More secure — packets take different routes
Implementation Implemented at the physical layer; simpler Implemented at the network layer; more complex
Scalability Less scalable — more users need more physical paths Highly scalable — handles large volumes and many users
Suitable for Real-time communication (voice calls, video conferencing) Emails, web pages, text messages, file downloads, high-volume non-live files

Do not write about “the speed of data transmission” in a packet/circuit switching answer — it earns no marks and in some questions is explicitly excluded. Talk about bit rate or bandwidth (bits per second) and the efficiency of the transmission instead.

  • Once the connection is made, it is available until the end of the transmission (suitable for long continuous transmission)
  • The dedicated path ensures a steady rate of data transmission, once connection has been made (because the whole bandwidth is available)
  • The dedicated path ensures data is less likely to be lost.
  • No intermediate delays once the circuit is established, enables real time transmission
  • No additional time/delay to reorder needed because data arrives in the order it was sent / data sent as a continuous stream

One mark for a benefit of packet switching (Max 1)

  • No need to tie up a communication line // path available to multiple users // bandwidth can be shared by multiple users
  • Possible to overcome failed / faulty / busy lines by re-routing packets
  • Individual packets can be resent if lost/damaged
  • Users only charged for the duration of connectivity
  • High rate of data transmission possible
  • Always uses digital networks so data is transmitted directly to the destination
  • Good security because all packets can take different routes // A more secure method because all packets can take different routes

Q4(b) One mark per difference (Max 2)

  • Circuit switching requires a dedicated line to be connected before the data transfer takes place; in packet switching, data transfer commences directly / straight away
  • In circuit switching, each data unit knows the entire path address, but in packet switching, each data unit only knows the final address (routers decide intermediate paths)
  • Circuit switching uses the whole bandwidth of the transmission path, but packet switching shares it with other users // circuit switching uses a constant high bandwidth; packet switching has variable bandwidth
  • In circuit switching each data unit follows the same route, but in packet switching, packets can follow any route
  • In circuit switching data arrives in the correct order but in packet switching it has to be reordered
  • Data remains intact / a continuous stream in circuit switching but is segmented in packet switching
  • Lost data in circuit switching requires the whole transmission to be resent, but individual packets can be resent in packet switching
  • Circuit switching doesn’t suffer data loss but packets can be lost in packet switching.

How packet switching is used to pass a message across a network

  • This is the syllabus requirement “Explain how packet switching is used to pass messages across a network, including the internet” — practise writing it as a numbered sequence

Worked answer: downloading a web page

  1. The web page (large message) is divided up into equal-sized data packets
  2. Each packet has a header, which includes the source IP address, destination IP address and sequence / packet number
  3. Each packet is dispatched/transmitted independently and may take a different route, with the optimum route chosen depending on congestion
  4. At each router the header is checked against the values stored in the routing table
  5. … to determine which router the packet needs to be sent to next (hopped / next hop)
  6. … the MAC address of the next router is added to the packet header
  7. The hop value is checked to see whether it equals zero; if it does, the packet is deleted
  8. Packets usually arrive out of order and the destination computer reassembles them, using the sequence number, building up the final web page
  9. If packets are missing / corrupted, a re-transmission request is sent

Worked answer: why a video call performs badly

  • Poor performance you might expect:
    • Picture and sound may not be in synchronisation (packets arrive at different times)
    • Video is not continuous — pauses caused by the time delay in reassembling packets
    • Degraded quality of sound and video, caused by competing traffic on the communication lines
    • Possible drop-out — packets take different routes, so packets can be lost
  • How circuit switching would improve it:
    • Only one route is used, so all packets arrive in the correct order
    • A dedicated channel means the full bandwidth is available
    • There is no loss of synchronisation

Across the internet ★

  • The message is carried by many networks owned by different organisations; each router only needs the destination IP address and its own routing table
  • No single device needs a map of the whole internet, which is what allows the network to keep growing
  • Large messages are split into equal-sized packets with a header (source/destination IP, sequence number) and a payload, each dispatched independently, possibly along different routes, then reassembled into the original message at the destination; missing or corrupted packets trigger a re-transmission request
