DDL & DML

What is DDL & DML?

  • Data Definition Language (DDL) is used to build and manage the structure of a relational database
  • It defines how data is stored by creating and modifying tables, fields, indexes, and relationships
  • Data Manipulation Language (DML) is used to manage the data stored within the database structures created by DDL
  • It deals with adding, updating, deleting, and retrieving data
  • Both DDL and DML use SQL syntax to interact with the database
  • DDL structures the database, while DML maintains the contents of the database
  • Most modern DBMSs use SQL to support both DDL and DML operations

Basic DDL commands

Command Purpose Example
CREATE DATABASE Creates a new database CREATE DATABASE SchoolDB
CREATE TABLE Creates a new table with specified fields and data types CREATE TABLE Students (StudentID INTEGER, Name VARCHAR(50))
Data types for attributes: Defines the type of data each field can store
CHARACTER Fixed-length text Name CHARACTER(10)
VARCHAR(n) Variable-length text (max length n) Email VARCHAR(100)
BOOLEAN True or False value IsActive BOOLEAN
INTEGER Whole numbers Age INTEGER
REAL Decimal numbers Score REAL
DATE Calendar date DateOfBirth DATE
TIME Time of day StartTime TIME
ALTER TABLE Changes an existing table (e.g. add or remove fields) ALTER TABLE Students ADD Email VARCHAR(100)
PRIMARY KEY (field) Sets a field as the primary key (unique identifier) PRIMARY KEY (StudentID) inside a CREATE TABLE or ALTER TABLE command
FOREIGN KEY (field) REFERENCES Table(Field) Sets up a foreign key relationship between tables FOREIGN KEY (CourseID) REFERENCES Courses(CourseID)

Example: School database

  • You are designing a database to store information about students and the courses they are enrolled in
  • Each student can enrol in many courses, and each course can have many students (a many-to-many relationship)
  • Three tables are needed:
    • Students – to store student details
    • Courses – to store course details
    • Enrolments – a link table to handle the many-to-many relationship
-- Create the Students table
CREATE TABLE Students (
    StudentID INTEGER,
    FirstName VARCHAR(50),
    LastName VARCHAR(50),
    DateOfBirth DATE,
    PRIMARY KEY (StudentID)
);
-- Create the Courses table
CREATE TABLE Courses (
    CourseID INTEGER,
    CourseName VARCHAR(100),
    Credits INTEGER,
    PRIMARY KEY (CourseID)
);
-- Create the Enrolments table to link Students and Courses
CREATE TABLE Enrolments (
    StudentID INTEGER,
    CourseID INTEGER,
    EnrolDate DATE,
    PRIMARY KEY (StudentID, CourseID),
    FOREIGN KEY (StudentID) REFERENCES Students(StudentID),
    FOREIGN KEY (CourseID) REFERENCES Courses(CourseID)
);

Basic DML commands

Retrieving data

Command Purpose Example
SELECT ... FROM Retrieves specific columns from a table SELECT FirstName, LastName FROM Students
WHERE Filters results based on a condition SELECT * FROM Students WHERE Age > 16
ORDER BY Sorts the results in ascending or descending order SELECT * FROM Students ORDER BY LastName ASC
GROUP BY Groups rows that have the same value in specified columns SELECT CourseID, COUNT(*) FROM Enrolments GROUP BY CourseID
INNER JOIN Combines rows from two tables where there is a matching key SELECT Students.FirstName, Courses.CourseName FROM Students INNER JOIN Enrolments ON Students.StudentID = Enrolments.StudentID INNER JOIN Courses ON Enrolments.CourseID = Courses.CourseID
SUM() Calculates the total of a numeric column SELECT SUM(Credits) FROM Courses
COUNT() Counts the number of rows (or non-null entries in a column) SELECT COUNT(*) FROM Enrolments
AVG() Calculates the average value of a numeric column SELECT AVG(Age) FROM Students

Data maintenance

Command Purpose Example
INSERT INTO Adds a new record to a table INSERT INTO Students (StudentID, FirstName, LastName) VALUES (1, 'Ali', 'Khan')
DELETE FROM Removes records from a table DELETE FROM Students WHERE StudentID = 1
UPDATE Modifies existing data in a table UPDATE Students SET Age = 17 WHERE StudentID = 1

Example: School database

  • You’re working with a school database containing three tables:
    • Students(StudentID, FirstName, LastName, Age)
    • Courses(CourseID, CourseName, Credits)
    • Enrolments(StudentID, CourseID, EnrolDate)
  • You want to query the database and maintain the data as students enrol in courses, update their details, or leave the school Querying
-- 1. Get the first and last names of all students
SELECT FirstName, LastName FROM Students;
-- 2. List students who are older than 16
SELECT * FROM Students WHERE Age > 16;
-- 3. List all students sorted alphabetically by surname
SELECT * FROM Students ORDER BY LastName ASC;
-- 4. Count how many students are enrolled on each course
SELECT CourseID, COUNT(*) FROM Enrolments GROUP BY CourseID;
-- 5. Show student names with the courses they are enrolled on
SELECT Students.FirstName, Students.LastName, Courses.CourseName
FROM Students
INNER JOIN Enrolments ON Students.StudentID = Enrolments.StudentID
INNER JOIN Courses ON Enrolments.CourseID = Courses.CourseID;
-- 6. Get the total number of course credits available
SELECT SUM(Credits) FROM Courses;
-- 7. Get the average age of all students
SELECT AVG(Age) FROM Students;

Maintaining

-- 1. Add a new student to the Students table
INSERT INTO Students (StudentID, FirstName, LastName, Age)
VALUES (4, 'Amira', 'Patel', 17);
-- 2. Enrol that student on CourseID 2
INSERT INTO Enrolments (StudentID, CourseID, EnrolDate)
VALUES (4, 2, '01/09/2025'); -- UK date format (DD/MM/YYYY)
-- 3. Update a student's age
UPDATE Students SET Age = 18 WHERE StudentID = 4;
-- 4. Delete a student who has left the school
DELETE FROM Students WHERE StudentID = 4;

1. Key point: DDL vs DML

Exercise 1.1 — State whether each statement is DDL or DML. (a) CREATE DATABASE SchoolDB (b) INSERT INTO Students (StudentID, FirstName, LastName, Age) VALUES (4, 'Amira', 'Patel', 17) © ALTER TABLE Students ADD Email VARCHAR(100) (d) UPDATE Students SET Age = 18 WHERE StudentID = 4 (e) SELECT FirstName, LastName FROM Students (f) DELETE FROM Students WHERE StudentID = 4

Answer — (a) DDL   (b) DML   © DDL   (d) DML   (e) DML   (f) DML

Exercise 1.2 — Explain the difference between DDL and DML, using the words structure and contents.

Answer — DDL is used to build and manage the structure of the database: creating and modifying tables, fields, keys and relationships. DML is used to manage the data contents stored inside those structures: adding, updating, deleting and retrieving data. DDL structures the database; DML maintains the contents.

Exercise 1.3 — Complete the paragraph with the correct words. “____ is used to create and modify the structure of a database. ____ is used to add, update, delete and retrieve data. Both DDL and DML use ____ syntax.”

Answer — DDL; DML; SQL.

3. Key point: Data types

Exercise 3.1 — Choose the most appropriate data type for each field from: CHARACTER, VARCHAR, BOOLEAN, INTEGER, REAL, DATE, TIME. (a) A registration number that is always exactly 8 characters, e.g. AB123456 (b) Whether a patient has been discharged © The mass of an object, e.g. 12.5 (d) The number of items in stock (e) The scheduled time of a lesson

Answer — (a) CHARACTER(8)   (b) BOOLEAN   © REAL   (d) INTEGER   (e) TIME

Exercise 3.2 — A database stores a person’s FirstName. Give two reasons why VARCHAR(30) is more appropriate than CHARACTER(30).

Answer — 1. VARCHAR stores only the characters actually used, so a short name such as ‘Ali’ uses little space, whereas CHARACTER(30) always reserves 30 characters. 2. Because the storage is variable, no padding of trailing spaces is needed and values compare cleanly, saving storage and simplifying data handling.

Exercise 3.3 — The database supports the data types: character, varchar, Boolean, integer, real, date, time. Write a SQL script to define the table MEMBER where MemberID is always exactly 4 characters, Name holds up to 20 characters, HasPaid holds a true/false value, and JoinedDate holds a calendar date. MemberID is the primary key. [4]

Answer

CREATE TABLE MEMBER (
    MemberID CHAR(4),
    Name VARCHAR(20),
    HasPaid BOOLEAN,
    JoinedDate DATE,
    PRIMARY KEY (MemberID)
);

4. Key point: ALTER TABLE

Exercise 4.1 — The Students table currently has the columns StudentID, FirstName, LastName. Write SQL to add a new column Email VARCHAR(100).

Answer — ALTER TABLE Students ADD Email VARCHAR(100);

Exercise 4.2 — Write SQL to remove the Email column that you just added.

Answer — ALTER TABLE Students DROP Email;

Exercise 4.3 — Give one reason why a database designer would use ALTER TABLE rather than deleting and recreating the table.

Answer — ALTER TABLE changes the structure of an existing table without losing the data already stored in it; recreating the table would require all existing data to be re-entered (and existing keys/relationships to be redefined).

5. Key point: PRIMARY KEY

Exercise 5.1 — For the table Students(StudentID, FirstName, LastName, Age), state which field is the most suitable primary key and justify your choice.

Answer — StudentID. It is guaranteed to be unique for every student, never changes, and is never blank. FirstName/LastName would not be suitable because two students could share the same name.

Exercise 5.2 — The Enrolments table stores StudentID, CourseID and EnrolDate. A student may appear in many rows and a course may appear in many rows, but each (StudentID, CourseID) pair appears only once. Write a CREATE TABLE statement for Enrolments using a composite primary key.

Answer

CREATE TABLE Enrolments (
    StudentID INTEGER,
    CourseID INTEGER,
    EnrolDate DATE,
    PRIMARY KEY (StudentID, CourseID)
);

Exercise 5.3 — State two properties of a primary key.

Answer — 1. It must be unique for every record in the table. 2. It cannot contain NULL (blank) values.

6. Key point: FOREIGN KEY & relationships

Exercise 6.1 — Using Students(StudentID, FirstName, LastName, Age) and Courses(CourseID, CourseName, Credits), write a CREATE TABLE statement for Enrolments that links to both tables with foreign keys.

Answer

CREATE TABLE Enrolments (
    StudentID INTEGER,
    CourseID INTEGER,
    EnrolDate DATE,
    PRIMARY KEY (StudentID, CourseID),
    FOREIGN KEY (StudentID) REFERENCES Students(StudentID),
    FOREIGN KEY (CourseID) REFERENCES Courses(CourseID)
);

Exercise 6.2 — Explain the purpose of a foreign key and describe what happens if you try to insert an Enrolments record with a StudentID that does not exist in the Students table.

Answer — A foreign key links a field in one table to the primary key of another table, enforcing referential integrity: every value entered must already exist in the referenced table. Inserting an enrolment for a non-existent student is rejected by the DBMS, so orphan records can never be created.

Exercise 6.3 — A Departments table has primary key DepartmentID. Write a CREATE TABLE statement for Staff(StaffID, Name, DepartmentID) where StaffID is the primary key and DepartmentID is a foreign key referencing Departments.

Answer

CREATE TABLE Staff (
    StaffID INTEGER,
    Name VARCHAR(50),
    DepartmentID INTEGER,
    PRIMARY KEY (StaffID),
    FOREIGN KEY (DepartmentID) REFERENCES Departments(DepartmentID)
);

10. Key point: GROUP BY

Exercise 10.1 — Write SQL to show how many students are enrolled on each course. Display the CourseID and the count.

Answer — SELECT CourseID, COUNT(*) FROM Enrolments GROUP BY CourseID;

Exercise 10.2 — A table Orders(CustomerID, OrderNo, Total) records customer purchases. Write SQL to show the total amount spent by each customer.

Answer — SELECT CustomerID, SUM(Total) FROM Orders GROUP BY CustomerID;

Exercise 10.3 — Explain why, in a GROUP BY query, every column in the SELECT list must either appear in the GROUP BY clause or be used inside an aggregate function.

Answer — The query collapses each group of rows into one output row. A column that is neither grouped nor aggregated has no single value per group, so the DBMS cannot decide which value to display.

11. Key point: INNER JOIN

Exercise 11.1 — Write SQL to show each student’s first name and the CourseID of every course they are enrolled on (join Students with Enrolments).

Answer

SELECT Students.FirstName, Enrolments.CourseID
FROM Students
INNER JOIN Enrolments ON Students.StudentID = Enrolments.StudentID;

Exercise 11.2 — Write SQL to show each student’s first name, surname and the name of each course they take. This needs a three-table join.

Answer

SELECT Students.FirstName, Students.LastName, Courses.CourseName
FROM Students
INNER JOIN Enrolments ON Students.StudentID = Enrolments.StudentID
INNER JOIN Courses ON Enrolments.CourseID = Courses.CourseID;

Exercise 11.3 — Explain what an INNER JOIN does and state when you would use one.

Answer — An INNER JOIN combines rows from two or more tables where there is a matching value, usually between a foreign key and a primary key. Only rows with a match in both tables appear in the result. It is used whenever related data stored in separate tables must be combined in a single query.

12. Key point: Aggregate functions (SUM, COUNT, AVG)

Exercise 12.1 — Write SQL to count the total number of students.

Answer — SELECT COUNT(*) FROM Students;

Exercise 12.2 — Write SQL to find the total number of credits available across all courses.

Answer — SELECT SUM(Credits) FROM Courses;

Exercise 12.3 — Write SQL to find the average age of all students.

Answer — SELECT AVG(Age) FROM Students;

Exercise 12.4 — Write SQL to show how many courses each student is enrolled on, ordered from the most courses to the fewest.

Answer

SELECT StudentID, COUNT(*)
FROM Enrolments
GROUP BY StudentID
ORDER BY COUNT(*) DESC;

13. Key point: INSERT INTO

Exercise 13.1 — Write SQL to add a new student to the Students table: StudentID 5, FirstName ‘Omar’, LastName ‘Hussain’, Age 16.

Answer

INSERT INTO Students (StudentID, FirstName, LastName, Age)
VALUES (5, 'Omar', 'Hussain', 16);

Exercise 13.2 — Write SQL to enrol StudentID 5 on CourseID 3 with the date 02/09/2025.

Answer

INSERT INTO Enrolments (StudentID, CourseID, EnrolDate)
VALUES (5, 3, '02/09/2025');

Exercise 13.3 — StudentID is the primary key of Students. What happens if you try to INSERT a new student without providing a StudentID?

Answer — The insert fails, because a primary key cannot be NULL (and must be unique). The DBMS rejects the record.

14. Key point: UPDATE

Exercise 14.1 — Write SQL to change the age of the student with StudentID 5 to 17.

Answer — UPDATE Students SET Age = 17 WHERE StudentID = 5;

Exercise 14.2 — The credits for the course with CourseID 1 are changed from 2 to 3. Write the SQL to update this.

Answer — UPDATE Courses SET Credits = 3 WHERE CourseID = 1;

Exercise 14.3 — Explain the importance of the WHERE clause in an UPDATE statement. What happens if it is left out?

Answer — The WHERE clause selects which rows to modify. Without it, the update is applied to every row in the table, changing all records — often losing correct data and being very hard to undo.

15. Key point: DELETE FROM

Exercise 15.1 — Write SQL to delete the student with StudentID 5 from the Students table.

Answer — DELETE FROM Students WHERE StudentID = 5;

Exercise 15.2 — Write SQL to delete all enrolments for CourseID 2.

Answer — DELETE FROM Enrolments WHERE CourseID = 2;

Exercise 15.3 — Explain what DELETE FROM Enrolments; does, and why a WHERE clause is usually needed when deleting.

Answer — Without a WHERE clause, DELETE FROM Enrolments; removes every row in the table (while keeping the table structure). A WHERE clause limits deletion to the intended records, avoiding accidental loss of all data.
